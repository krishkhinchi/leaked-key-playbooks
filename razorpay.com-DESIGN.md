# Design System Inspired by Razorpay

## 1. Visual Theme & Atmosphere

Razorpay's design system embodies a modern fintech aesthetic grounded in trust, clarity, and forward momentum. The visual language combines a bold primary blue accent with a sophisticated neutral palette, creating interfaces that feel both approachable and enterprise-ready. Depth emerges through subtle layering of shadows and color blocking rather than heavy visual effects. The typography system uses multiple font families strategically—geometric grotesques for display and navigation, humanist sans-serifs for body copy—to establish hierarchy and guide attention. Generous whitespace and carefully calibrated spacing create breathing room, while the color palette remains intentionally restrained to prioritize content and interaction. The aesthetic suggests a payment platform built for speed and reliability, with visual warmth balanced against professional restraint.

**Key Characteristics**

- Bold primary blue (`#0B72E7`) drives interactive elements and brand presence
- Neutral black (`#0B0C10`) and deep grays anchor the hierarchy
- Micro-elevations using single-layer shadows for subtle depth
- Multi-font strategy: Host Grotesk for display impact, MulishVariable for navigation, Muli for body
- High contrast between foreground and canvas ensures legibility
- Pill-shaped buttons and rounded cards soften the technical aesthetic
- Generous section spacing (`{spacing.band}` — 48px) creates rhythm
- Decorative gradients with translucent overlays add visual interest without clutter

### Principles

- **Tracking as personality**: Display sizes use negative letter-spacing (`-4.88px` to `-2.93px`) for a compressed, modern feel; body text remains neutral
- **Multi-font semantics**: Host Grotesk signals prestige and modernity; MulishVariable provides warm, approachable navigation; Muli offers reliable body readability
- **Hierarchy through contrast**: Large 122px display sits atop 14px nav, creating extreme visual separation; body sits at a comfortable 15–16px
- **Weight economy**: Only three weights used (400, 600, 700, 800) to avoid bloat; 700 dominates emphasis, 400 for clarity
- **Line height calibration**: Display sizes tightened to 0.87–0.92 for impact; body relaxed to 1.5–1.6 for scanning

## 5. Layout Principles

### Spacing System

The spacing system uses an 8px-based scale for consistency and rhythm:

- `{spacing.xxs}` = 4px — minimal, used for micro-interactions
- `{spacing.xs}` = 8px — tight spacing between elements
- `{spacing.sm}` = 12px — small margins and padding
- `{spacing.md}` = 16px — default padding for components
- `{spacing.lg}` = 20px — comfortable spacing within cards
- `{spacing.xl}` = 24px — section internal padding
- `{spacing.xxl}` = 28px — generous spacing
- `{spacing.xxxl}` = 32px — large section margins
- `{spacing.section}` = 40px — between major sections
- `{spacing.band}` = 48px — full-width band padding, defines vertical rhythm

**Usage Context**: Cards use `{spacing.lg}` or `{spacing.xl}` internally. Section-to-section gaps use `{spacing.section}` or `{spacing.band}`. Inline element spacing relies on `{spacing.xs}` to `{spacing.md}`.

### Grid & Container

- **Max Width**: 1440px (measured at largest breakpoint)
- **Content Column**: 1400px (1440px minus 40px padding on each side)
- **Grid Columns**: 2-column layout is primary across breakpoints (375px to 1440px)
- **Horizontal Padding**: 
  - Mobile (375px–768px): `{spacing.xl}` (24px) per side
  - Tablet & Desktop (1024px+): `{spacing.xl}` (24px) to `{spacing.lg}` (20px) per side at 1440px
- **Section Patterns**: Hero + content + band + content + footer structure; bands use full viewport width with centered content

### Whitespace Philosophy

Whitespace is treated as a design tool to guide attention and create visual rest. Large display sizes (48px to 122px) sit above generous top margins (`{spacing.band}` — 48px). Section-to-section gaps are consistent (`{spacing.section}` — 40px), creating predictable rhythm. Card interiors breathe with `{spacing.lg}` (20px) or `{spacing.xl}` (24px) padding. Body text lines sit at 15–16px with 1.5–1.6 line-height for legibility, never compressed. The hero section uses translucent gradient overlays and negative space to establish a sense of openness, signaling a premium, trustworthy experience.

### Border Radius Scale

- `{rounded.none}` = 0px — full-width sections, images, sharp elements
- `{rounded.xs}` = 2px — badges, small inline accents
- `{rounded.sm}` = 4px — buttons in compact layouts
- `{rounded.md}` = 6px — input fields, secondary buttons
- `{rounded.lg}` = 8px — primary buttons, medium containers
- `{rounded.xl}` = 12px — cards, panels, modal windows
- `{rounded.full}` = 9999px — pill-shaped buttons, circular avatars, icon-only buttons

Component Radius Application: Buttons measure `{rounded.lg}` (8px); cards measure `{rounded.xl}` (12px); badges measure `{rounded.xs}` (2px); images and full-width sections measure `{rounded.none}` (0px).

### Border Widths

- **Thin** = 1px — default border for inputs, secondary buttons, and hairline dividers
- **Medium** = 2px — focus outlines on interactive elements (not commonly applied to borders in this system)
- **Thick** = Not used in extraction; the system relies on single 1px strokes for definition

Inputs and secondary buttons apply `1px` borders. Focus states layer a `2px` outline on top. No thick borders are measured in the primary component set.

## 6. Depth & Elevation

### Shadow Hierarchy

| Level | Treatment | Use |
|---|---|---|
| Flat | None | Inline text, backgrounds, flat UI zones |
| Micro (sm) | `rgba(0, 0, 0, 0.05) 2px 4px 9px 1px, rgba(0, 0, 0, 0.04) 0px 1px 1px 0px` | Cards, subtle lift |
| Small (md) | `rgba(0, 0, 0, 0.05) 2px 4px 9px 1px` | Button default state, mild depth |
| Medium (lg) | `rgba(0, 0, 0, 0.09) 0px 3px 13px 0px, rgba(0, 0, 0, 0.14) 0px 1px 5px 0px` | Button hover, elevated panels |
| Large (xl) | `rgba(0, 0, 0, 0.09) 0px 0px 6px 0px` | Dropdowns, popovers, floating UI |

**Shadow Philosophy**: The elevation strategy is classified as **layered-micro** — shadows use multiple semi-transparent layers stacked to create barely-there depth. No single thick shadow dominates; instead, a combination of a primary shadow (for distance) and a secondary shadow (for definition) creates a refined, modern aesthetic. On hover, button shadows elevate from `md` to `lg`, signaling interactivity without jarring visual shifts. The system prioritizes **color blocking** (surface color changes) over shadows for primary depth cues.

### Opacity Levels

The system employs opacity shifts to create subtle visual feedback:

- **1% (0.01)** — Imperceptible, used for extremely faint overlays
- **30% (0.30)** — Disabled button fill, faint background tint
- **40% (0.40)** — Disabled state text, secondary badges
- **60% (0.60)** — Hover overlay on secondary elements
- **70% (0.70)** — Semi-transparent text on color backgrounds
- **90% (0.90)** — Nearly opaque, near-final states

Opacity is used sparingly; most state changes rely on color shifts rather than transparency alone.

### Z-index / Layering

- **Base Layer** = 1–6 — Default cards, standard page content
- **Dropdown Layer** = 10–12 — Dropdowns, tooltips, secondary floating UI
- **Modal/Overlay Layer** = 20+ — Modal dialogs, full-page overlays, toast notifications

The stacking order is minimal and deliberate. Dropdowns sit comfortably above page content at z-index 10; modals break at 20 to ensure they eclipse all other UI.

## 7. Do's and Don'ts

### Do

- **Use the primary blue (`#0B72E7`) for all primary CTAs** — it is the brand anchor and drives immediate recognition and trust
- **Apply card shadows (`sm`) to lift content subtly**; reserve larger shadows (`lg`, `xl`) for interactive hover states or modals
- **Set body copy at `{typography.body-sm}` (15px) or `{typography.body-md}` (16px)** with line-height 1.5 or 1.6 for comfortable reading
- **Stack display sizes using negative tracking (`-2.93px` to `-4.88px`)** to maintain the compressed, modern headline aesthetic
- **Center content within a 1400px max-width container** with 20–24px horizontal padding per side
- **Use `{spacing.band}` (48px)** for padding inside full-width colored sections or hero bands
- **Apply pill-shaped buttons (`{rounded.lg}` 8px or `{rounded.full}` for icon-only)** to soften the interface
- **Layer cards with `{rounded.xl}` (12px)** for a cohesive, premium appearance
- **Maintain consistent link color (`#528FF0`) for all inline hyperlinks** unless in a dark or branded context
- **Test button hover states** to ensure the shadow lift and background deepening feel responsive
- **Reserve uppercase styling for badges and labels** only; use standard case for body and navigation

### Don't

- **Don't use decorative accent colors (`#26292D`, `#2F3B53`, `#0000EE`, `#3987F0`) as interactive fills**; they have no measured role and will confuse users
- **Don't apply tracking below `-0.2px` to body copy**; compression is reserved for display sizes 18px and above
- **Don't override line-height for body text below 1.5**; tight line-height reduces legibility
- **Don't stack more than two shadow layers** on a single element; use the predefined levels (`sm`, `md`, `lg`)
- **Don't use rounded corners smaller than `{rounded.md}` (6px) for interactive elements**; they can feel fragile
- **Don't exceed 24px horizontal padding inside cards**; use `{spacing.xl}` as maximum
- **Don't set navigation link color to black (`#000000`) or ink (`#02042A`)** on light backgrounds; use body text color or darker neutral
- **Don't introduce new semantic colors (error red, warning yellow, success green) beyond the measured palette**; the site does not declare them
- **Don't use weight 800 for body text**; reserve 800 for display and heading emphasis
- **Don't rely on opacity alone for disabled states**; combine opacity reduction with muted text color
- **Don't nest dropdowns or modals beyond z-index 20** without re-evaluating the information hierarchy

## 8. Responsive Behavior

### Breakpoints

| Viewport | Content Column | Grid Columns | Nav Links Visible | Menu Toggle | Largest Heading | Body Font | Section Padding-X |
|---|---|---|---|---|---|---|---|
| 375px (Mobile) | 343px | 1 | 1 | Yes | 48px (Display SM) | 12px–14px | 24px |
| 768px (Tablet) | 736px | 2 | 1 | Yes | 48px (Display SM) | 12px–14px | 24px |
| 1024px (Desktop) | 984px | 2 | 5 | No | 110px (Display LG) | 12px–14px | 24px |
| 1280px (Large Desktop) | 1240px | 2 | 5 | No | 110px (Display LG) | 12px–14px | 24px |
| 1440px (XL Desktop) | 1400px | 2 | 5 | No | 122px (Display XXL) | 12px–14px | 20px |

**Collapse Point**: Navigation transitions to hamburger menu between 768px and 1024px. The toggle appears at 768px when visible link count drops to 1; by 1024px, the full nav re-expands to 5 links across.

**Key Transitions**:
- **375px → 768px**: Single-column to two-column layout; heading size holds at 48px
- **768px → 1024px**: Menu toggle disappears; heading jumps to 110px; nav expands to full width
- **1024px → 1440px**: Heading grows to 122px; section padding compresses slightly from 24px to 20px; content column expands but maintains margin proportions

### Touch Targets

- **Minimum touch target size**: 48px × 48px (buttons, icon buttons, nav toggles)
- **Comfortable tap zone**: 56px × 56px for frequently-tapped elements (primary CTAs)
- **Spacing between touch targets**: Minimum `{spacing.md}` (16px) gap to avoid accidental taps
- **Link padding in body text**: Inline links inherit body line-height; recommended padded area is at least `{spacing.sm}` (12px) per side

### Collapsing Strategy

- **Navigation**: Switches to hamburger menu (three-line toggle) at 768px and below; expands back to horizontal list at 1024px
- **Hero section**: Display headline remains 48px on mobile; jumps to 110px at 1024px, then 122px at 1440px
- **Card grid**: Single-column stack on mobile (375px); two-column grid from 768px onward
- **Section padding**: Consistent 24px left/right on mobile and tablet; reduces to 20px at 1440px to allow max-width container breathing room
- **Image scaling**: Full-width images on mobile (375px); constrained to max-width container on desktop; border-radius remains `{rounded.none}` (0px) throughout
- **Button sizing**: Buttons remain full-width or flex-fit on mobile (375px–768px); constrained width with hover effects on desktop (1024px+)
- **Typography**: Body font size holds at 14–15px across all breakpoints; leading (line-height) remains 1.5–1.6 for consistency; display sizes scale aggressively (48px → 122px)

## 10. Known Gaps

- **Semantic color ramp not declared**: The site does not expose error (red), success (green), or warning (yellow) colors in measured states. No semantic status palette exists; if one is needed, it must be defined separately.

- **Interaction states partially extracted**: Stylesheets captured hover, active, and focus-visible states for buttons, links, and navigation. However, disabled and loading states may be incomplete or absent from the extraction; full behavior should be validated on-site.

- **Six decorative accent colors without measured roles**: Colors `#26292D`, `#2F3B53`, `#0000EE`, `#3987F0`, `#0B72E7` (decorative variant), and `#5F6C7D` (accent variant) appear in the palette but have no clear interactive purpose. They may be used only for gradients, illustrations, or background textures; treat them as decorative only.

- **Gradient overlays recorded verbatim but context incomplete**: Three linear gradients were extracted (translucent blue-to-green overlays) but their exact DOM targets and responsive behavior were not fully documented. Apply conservatively to hero sections and full-width bands.

- **Form validation and error states not measured**: The extraction did not capture invalid input styling, error messages, or success confirmations. These should be defined when form capture is revisited.

- **Animations and transitions not extracted**: The system may include slide, fade, or transform micro-interactions (e.g., button `transform: translateY(-2px) scale(1.01)` on hover); these are present in the interaction data but lack full timing and easing curves.

- **Dark mode implementation incomplete**: The extracted tokens represent light-mode primarily. A full dark-mode palette was not measured across all components; surfaces and text ramps may differ in inverse contexts.

- **Cross-origin stylesheet limits**: Some interactive CSS may have been declared in third-party stylesheets (Framer, Chakra UI CSS variables) that could not be fully read. The design tokens reflect the visible, measurable subset.

- **Authenticated/gated surfaces not visited**: The design system covers public-facing pages only. Dashboards, account settings, or backend UIs behind login were not extracted.

- **Micro-interactions and focus rings incomplete**: While focus states (outlines, box-shadows) were measured, the full focus management strategy and accessible focus ring contrast ratios were not validated to WCAG standards.
